# 工作流系统使用指南

## 1. 概述

工作流系统是现有目标系统（/goal）的扩展，支持更灵活的工作节点设置。与线性目标不同，工作流支持：

- **DAG结构**：节点间可有多依赖关系
- **多种节点类型**：执行、条件、并行、人工审批、子工作流
- **混合模式**：LLM生成初始工作流 + 用户手动调整

## 2. 快速开始

### 2.1 创建工作流

```
/workflow create 实现用户注册功能
```

LLM会自动拆解为多个节点，生成初始工作流结构。

### 2.2 查看工作流状态

```
/workflow status
```

显示当前工作流的进度、节点状态和依赖关系。

### 2.3 执行工作流

```
/workflow run
```

开始执行工作流，LLM会按照节点顺序执行任务。

## 3. 节点管理

### 3.1 添加节点

```
/workflow node add 创建用户表
```

### 3.2 删除节点

```
/workflow node remove n3
```

### 3.3 编辑节点描述

```
/workflow node edit n2 实现注册API接口
```

### 3.4 设置节点类型

```
/workflow node type n4 HITL
```

支持的节点类型：
- `ACTION`：执行动作（默认）
- `CONDITION`：条件判断
- `PARALLEL`：并行执行
- `HITL`：人工审批
- `SUBFLOW`：子工作流
- `START`：开始节点
- `END`：结束节点

## 4. 依赖管理

### 4.1 建立依赖关系

```
/workflow link n1 n2
```

表示节点n1完成后才能执行节点n2。

### 4.2 移除依赖关系

```
/workflow unlink n1 n2
```

### 4.3 添加条件分支

```
/workflow branch n3 --if "test.passed" --then n4 --else n5
```

表示：
- 如果条件`test.passed`为真，执行节点n4
- 如果条件为假，执行节点n5

## 5. 执行控制

### 5.1 暂停工作流

```
/workflow pause
```

### 5.2 恢复工作流

```
/workflow resume
```

### 5.3 重试失败节点

```
/workflow retry n3
```

### 5.4 跳过节点

```
/workflow skip n4
```

### 5.5 清除工作流

```
/workflow clear
```

## 6. 工作流结构示例

### 6.1 线性工作流

```
[start] → [n1: 创建用户表] → [n2: 实现注册API] → [n3: 验证邮箱] → [end]
```

### 6.2 分支工作流

```
[start] → [n1: 创建用户表] → [n2: 实现注册API] → [n3: 条件判断]
                                                    ↓
                                          [n4: 验证邮箱] → [end]
                                          [n5: 发送欢迎邮件] → [end]
```

### 6.3 并行工作流

```
[start] → [n1: 创建用户表] → [n2: 并行执行]
                              ↓
                    [n3: 实现注册API] → [n4: 验证邮箱]
                    [n5: 发送欢迎邮件] → [end]
```

## 7. 工具支持

### 7.1 workflow_mark_node

标记节点完成，LLM每完成一个节点后调用此工具。

### 7.2 workflow_visualize

可视化显示工作流结构，返回节点列表、依赖关系和执行状态。

## 8. 存储结构

工作流数据存储在：
```
~/.agent4j/workspace/{hash}/workflows/{sessionId}.jsonl
```

每个会话一个文件，JSONL格式存储。

## 9. 与现有系统的兼容性

### 9.1 向后兼容

- 保留现有`/goal`命令作为快捷方式
- `/goal set <描述>` 自动转换为简单线性工作流
- 现有目标数据可自动迁移

### 9.2 渐进式升级

- 第一阶段：实现基础工作流结构（已完成）
- 第二阶段：添加条件和并行支持（部分完成）
- 第三阶段：添加子工作流和高级特性（待实现）

## 10. 最佳实践

### 10.1 节点粒度

- 每个节点应该是一个独立可验证的任务
- 避免节点过于细粒度（如"保存文件"）或过于粗粒度（如"实现整个功能"）

### 10.2 依赖关系

- 明确节点间的依赖关系，避免循环依赖
- 使用条件分支处理不同场景

### 10.3 错误处理

- 为关键节点设置验证命令
- 合理设置重试次数
- 使用人工审批节点处理敏感操作

### 10.4 工作流可视化

- 定期使用`/workflow show`查看工作流结构
- 使用`/workflow status`监控执行进度

## 11. 故障排除

### 11.1 工作流创建失败

- 检查会话是否已初始化
- 检查工作区是否已初始化

### 11.2 节点执行失败

- 使用`/workflow retry`重试失败节点
- 检查错误日志，分析失败原因
- 必要时调整节点描述或依赖关系

### 11.3 工作流卡住

- 使用`/workflow status`查看哪些节点被阻塞
- 检查依赖关系是否正确
- 使用`/workflow skip`跳过阻塞节点

## 13. 示例：用户注册功能

### 13.1 创建工作流

```
/workflow create 实现用户注册功能，包括创建用户表、实现注册API、验证邮箱、发送欢迎邮件
```

### 13.2 查看工作流结构

```
/workflow show
```

输出：
```
节点:
  start. 开始 (START)
  n1. 创建用户表 (ACTION)
  n2. 实现注册API (ACTION)
  n3. 验证邮箱 (ACTION)
  n4. 发送欢迎邮件 (ACTION)
  end. 结束 (END)

依赖关系:
  start -> n1
  n1 -> n2
  n2 -> n3
  n3 -> n4
  n4 -> end
```

### 13.3 添加条件分支

```
/workflow branch n3 --if "email.valid" --then n4 --else n5
/workflow node add 重新验证邮箱
/workflow link n5 n3
```

### 13.4 执行工作流

```
/workflow run
```

### 13.5 监控执行进度

```
/workflow status
```

输出：
```
──────────────────────────────────────
🔄 工作流：实现用户注册功能
状态：🟢 进行中

进度：2/5 (40%)

✅ start. 开始 (START)
✅ n1. 创建用户表 (ACTION)
🔵 n2. 实现注册API (ACTION)
⬜ n3. 验证邮箱 (CONDITION)
⬜ n4. 发送欢迎邮件 (ACTION)
⬜ n5. 重新验证邮箱 (ACTION)
⬜ end. 结束 (END)
──────────────────────────────────────
```

## 14. 总结

工作流系统提供了一个灵活、强大的任务编排框架，支持从简单的线性任务到复杂的分支、并行工作流。通过混合模式，用户可以充分利用LLM的自动化能力，同时保持对手动调整的完全控制。
